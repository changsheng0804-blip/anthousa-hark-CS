# 规则预演 v3 · 户籍册 + 治理分层（刘线，2026-10-12）

> 实验，不上线：账本目录（proposals/ rules/ chronicle/ engine/ data/ i18n/）、街区页、v0/v1/v2 目录一字未改；v0 数据层、v1 引擎与打分、v1 预计算缓存只读复用。
> 同一台沙箱（2 核、8 GB）。v1/v2 的数字取自它们的报告（同一沙箱实测），v3 的数字全部是本轮实测，见 `out/*.json`。
> 所有者的洞见：按街分配房东延续下去就是「户籍制度」；户籍上加治理分层，就是政治管理体系的雏形。本轮把它落成数据结构并用账本事件验证。

## 1. 一句话结论

**户籍册立得住，而且顺手修好了 v2 最大的一笔对账缺口；治理树能把账本上的每一道政令送到户、把四份请愿送到采纳的那一级；关系全部变成 O(1) 读字段——全城编册 0.12 秒、单户查询 2–3 微秒。它是一个「能运转的行政骨架」，还不是「政治体系」：缺财政、司法、真正的选任/继承、偏袒与危机动员。下一步选财政（§8）。**

要点数字（干山页面范围，AF60）：
- **页面房子 ≠ 6 户一栋：v2 的对账框错了。** 用 v0 同一个仿射去对**全城**账本房屋，页面房子到最近账本房屋中位 **8.8 px**（p90 15.5 px，约一栋房子宽）。页面上的「干山」其实横跨账本的**广场区、港口区、干山区**三个街区；页面 11/38/48/54 年的拆房与账本同年同街区的拆房对得上（38 年 140/195、48 年南港大火 71/91、54 年 17/17）。AF60：4,383 户登记在 **3,460 栋账本房屋**（广场区 1,944、港口区 919、干山区 597），**每栋 1.27 户、6.91 人**（全城账本平均 9.0 人/栋）。v2 的「×6」「面包簿 ×3」「T1 人口 ×3.56」都来自只拿干山区 746 栋去比。
- **面包簿 = 账本房屋，一栋一本**：3,460 本 × 11.65 份 = 40,326 份口粮，屋里按「房主 → 租户（搬来先后）」分，**22,283 / 23,912 人吃得上**（v2 有房户规则只有 12,912 人），没饼的 1,629 人全在 2–6 户挤一栋的房子里。
- **年龄口径改 14**：缺男丁户 **615**，与 chronicle 一致（v2 规则 532）。户数、人数、十人以上户 469、运水人家 742、阿里乌派 2,435 全部与账本/草案一致。
- **治理树（AF60）**：城市长官 1（机构）→ 区长 **3** → 坊长 **23**（110 条街，≈每 5 条街一坊，Notitia 比例）→ 房主 **3,460**（其中 771 户有租户）→ 租户 **923**。教会树：2 位主教 → 2 个教区 → 教区长老 **46** → 3,519 户（还拜旧神 864 户不入教区）。行会头 **18**、兵户 774。每个节点都是一户；21 年里区长换人 2 次、坊长 9 次、长老 19 次、行会头 6 次。
- **政令下行 / 诉求上行**：账本 54/57/62/65 年的拆房按登记房屋落到户——**17 / 6 / 17 / 10 户被拆**（页面原来只有 54 年那 17 户）；57 年征工 140 户按「区 → 坊 → 户」配额，大街出工占比 **77.1%（户数占比 81.9%）**，v2 每街 2 户只有 38.6%；四份请愿分别在城市长官（水、挤）、干山区长（孤寡）、阿里乌派主教（信仰）被采纳，账本耗时 2/3/5/4 年。
- **交叉点**：v1 引擎原样跑、只换「谁有房 / 谁是房东 / 14 岁」，v1 交叉点**逐条复现 3,172 / 7,035（45%）、同一对人家 4,203（60%）**，前 100 名同对 81、前 8 名同对 6/8；接线对照（三处都不换）= 7,035/7,035 全同、分数全同。**新增政治交叉点 496 个**（全城合成 949），32 种骨架，前 5 种占 74%。
- **计算量**：干山编册 21 年 **0.034 s**、全城（合成）**0.124 s**、账本规模（干山 ×7 拼接，3.07 万户/年、16.7 万人）**0.225 s**；单户全记录查询 **1.8 μs**（全城 2.7 μs）、两户关系 **0.7 μs**（全城 1.2 μs）；户籍新增存储每户 **24.5 B / gzip 11.5 B**。

## 2. 户籍册（`prep3.py` 底册、`registry.py` 编册与查询）

### 2.1 一条户籍记录

| 字段 | 来源 | 推得出 / 假设 |
|---|---|---|
| 登记房屋（账本房屋 ID） | 页面房子 → 仿射 40 px 内最近 8 栋账本房屋，按「拆毁年对得上 → 建成年接近 → 距离」挑那年站着的一栋；一栋都不站着就暂挂到最近站着的（R1/R2） | 仿射是 v0 的，账本房屋是 world.json；挑法是假设。21 年里只有 347 个房子·年要暂挂 |
| 房主 / 租户 | 同一栋账本房屋里：非暂挂 → 搬来最早 → 户键 的一户是房主，其余是租户（R3） | 假设（账本只有房屋，没有房契） |
| 房东 | = 本屋房主（查询，不再分配） | 由 R3 推出；**v0/v1 的「同街 6 家容量顺序贪心」不再需要** |
| 区 | 登记账本房屋的街区（众数） | 账本 |
| 街 / 坊 | 页面街名（谭线空间事实）；坊 = 同区内按街中心 Hilbert 排序、每 5 条街一坊 | 街：事实；坊：假设 G2（Notitia 全城 322 条街、65 个 vicomagistri ≈ 5:1） |
| 面包簿 | 随登记房屋：一栋一本，每本口粮 = 粮食上限 ÷ 全城站着的账本房屋数（T2）；屋里 房主 → 租户 依次分（T2c） | 上限、房屋数：账本；配给量与门内顺序：假设 |
| 教区 | 按信仰分线：尼西亚派 49 起阿纳斯塔西娅；阿里乌派 51 年被请出、52–63 城外木院、64 起城门外砖堂 | 账本（chronicle） |
| 施舍 | 缺男丁（**14 岁口径**）∧ 本派那年有施舍的地方；65 起寡妇孤儿之家不分派 | 年份：账本；量：假设 T4 |
| 行会 / 征工组 / 兵营 / 籍贯 | 行当 / = 坊 / 儿子当兵年、驻军街区或兵营 220 px 内 / 页面家谱 | 征工组 = 坊是假设 G3 |

全部关系都是「读字段」：房东 = `owner[登记房屋]`，坊长 = `坊长现任[坊]`，同一面包簿 = 同屋，同教区 = 同派同年同堂……`Query.rec(F, Y)` 一次给全，`Query.rel(F, G, Y)` 比字段。与编册结果逐条核对 3,000 次，0 差异。

## 3. 治理分层

### 3.1 层级概览（AF60；括号内全城合成）

```
民政树  城市长官（机构，皇帝任命）
        ├─ 区长 ×3（×4）        —— 区内够格房主里屋里人家最多、搬来最早的一户
        │   └─ 坊长 ×23（×168）  —— 每坊 ≈5 条街（110 条街 / 23 坊；全城 804 合成街）
        │       └─ 房主 ×3,460（×16,281）—— 一栋账本房屋一户，持面包簿
        │           └─ 租户 ×923（×0，合成人家一栋一户）
教会树  尼西亚派主教 → 阿纳斯塔西娅（1,084 户）    阿里乌派主教 → 城外木院（2,435 户）
        └─ 教区长老 ×46（每 派×坊 一户；×335）
行会树  行会（6 个行当）→ 行会头 ×18（每 区×行当；×65）
军营    城门兵营 → 兵户 774（×3,386）
```

| 层 | 从账本推得出的 | 假设 |
|---|---|---|
| 城市长官 | 拆房、新区、新蓄水池都是账本「已采纳的建设」，只能由全城一级下令 | 不是户（君士坦丁堡的 praefectus urbi 由皇帝任命） |
| 区 | 账本 5 个街区（干山页面跨 3 个） | 君士坦丁堡是 14 区；账本只有 5 个，不硬凑 14 |
| 坊 | 页面街名 | 每 5 条街一坊（Notitia：第一区 29 条街、5 个 vicomagistri；全城 322 条街、65 个）。出处：<https://digiliblt.it/teidocs/idno/DLT000374>、<https://en.wikipedia.org/wiki/Notitia_Urbis_Constantinopolitanae> |
| 房主 / 租户 | 账本房屋 | R3 |
| 教区 | chronicle 写明的四处礼拜地点与年份 | 一派一个教区（干山页面范围） |
| 长老 / 行会头 / 区长 / 坊长人选 | — | 选任规则 G1（连任；出缺选屋里人家最多 → 搬来最早）。坊长 23 人全是「屋里有租户」的房主，平均 6.0 口 |

政治关系本身就是户籍字段：例如 AF60 的三位区长是广场区 **3638:2 马可家**（尼西亚派，色雷斯人，陶匠——57 年时他还是坊长）、港口区 11497:40 提摩太家（阿里乌派）、干山区 11970:43 卡利尼科斯家（还拜旧神）。坊长的信仰：阿里乌派 11、还拜旧神 8、尼西亚派 4（户数比 2,435 : 864 : 1,084）。

## 7. 结论：算不算一个可运转的政治管理体系雏形？

**算「行政骨架」，不算「政治体系」。**

已经能运转的：
1. **登记**：每户一条记录，所有经济政治关系都是字段或字段的比较，换年份就是换一列，O(1)。
2. **层级**：民政、教会、行会、军营四棵树共享叶子（户），每个节点由真实户担任，有连任和出缺补选。
3. **下行**：账本每一道政令都能按树送到户（谁被拆、谁出工、谁多领了面包、谁失去或领回施舍），总量与账本守恒。
4. **上行**：请愿按树聚合，停在有权采纳的最低一级；跨区的事必须走到城市长官（最近公共上级），这一点自动给出了「孤寡院要走 5 层」这种结构性的慢。
5. **冲突**：两棵树在同一户、同一屋檐下相遇的地方就是政治故事（496 个），而且头部故事与经济线叠在一起（前 8 里 6 对人家在 v1 引擎里也有交叉点）。

缺的块（按要紧程度）：
1. **财政 / 税收**：口粮只按上限平均分，凑铜板、征工没有金额，请愿为什么等 2–5 年说不出来——没有「钱从哪来、谁截留」，体系就没有约束。
2. **偏袒 / 腐败**：现在只标出了利益冲突的**位置**（坊长点名、门内分配、同乡区长），规则本身是中性的；要能测，得先有财政流量，才能看每一层截留多少。
3. **选任与继承**：只有「屋里人家最多 → 搬来最早」一条，没有任期、推举、世袭或上级任命的区别；职位交接时的冲突（21 年里区长换 2 次、坊长 9 次）还没有故事。
4. **司法**：没有纠纷、判决、谁来裁——债、拆房补偿、租约都只是「发生了」。
5. **危机动员**：灾年（45、51）的借粮、57 年的征工都是定额摊派；火灾/瘟疫时的救济、征兵没有按树动员的规则。
6. **人对人的关系还在树外**：恩主、债、师傅仍是 v1 的顺序贪心；全城合成人家一栋一户没有租户；页面 61 年后没有迁徙，城墙外新区接不住「挤」的请愿；水源规则仍与账本叙述相反。

## 8. 下一步（选定）：财政——把「按户籍摊派」做成一本守恒的账

**做法**：在户籍 + 民政树上加一层收支：城市长官 → 区 → 坊 → 房主 → 户，每级记「收了多少、交上去多少、发下来多少」。先只接账本已有的量：口粮（粮食上限 ÷ 账本房屋）、每座蓄水池 +15,000 人的水、拆房栋数、54/62 年凑铜板与 57 年征工的户数；金额与每级截留比例标「假设」并做敏感性。请愿的采纳改成「那一级的结余够不够」决定，用账本的 2/3/4/5 年去校。

**为什么选它**：
- 它是其余缺块的前提：偏袒/腐败 = 某一级截留偏离均值；危机动员 = 财政在灾年的再分配；选任冲突 = 谁控制这一级的钱。没有流量，这些都只能标位置。
- 它最能接账本：账本有上限、栋数、年份，户籍已经让每一份口粮、每一栋拆房落到了具体的户，加收支只是在已有的树上做加法，编册仍是每年一次向量化（预计 +1–2 ms/年）。
- 它直接回答本轮唯一说不出的账本事实：四份请愿为什么分别等了 2、3、4、5 年。

没选的：①把恩主/债/师傅收进户籍（应在财政之后：债本身就是财政关系）；②司法（没有可对账的账本量）；③修水源规则与 61–70 年迁徙（要改页面推演或规则，属方向性变化，先问所有者）。

## 9. 已知问题与判断

1. **任务书写「用账本 746 栋（干山）修正谁有房」**，本轮改用全城账本房屋做底册：页面房子与全城账本房屋中位 8.8 px 对得上，而且拆房年份逐街区吻合；只用 746 栋会把广场区、港口区的 3,600 多户硬塞进干山区。干山区那部分的数（597 栋有人家）单独列在 §4.3。chronicle/61_70.md 把「克塞罗洛福斯这一角 4,383 户」和「山上的房子 746 座」并列，两者其实不是同一片地——这是账本叙述的口径问题，本轮没动 chronicle。
2. 底册挑法（R1/R2）、房主规则（R3）、坊（G2）、选任（G1）、征工点名（G3）、口粮与门内顺序（T2/T2c）都是假设；推得出的只有房屋、街区、年份、上限、户与人。
3. 账本拆房在页面范围内的那几栋，页面房子还站着：户籍上「迁籍」，页面上照住。要让页面也拆，得改页面推演（不在本轮权限内）。
