# 节点流水线（CS 线，2026-10-17）
主人定的方向：底账 → 节点 → 渲染器。学 WorldGacha（oyasumi-gamedev）的方法，没用它的代码。
- `build.py <q>` 按顺序跑七个节点：地、水、栈桥、街、房、地标、空地，写出 `docs/living/nodes/<q>/nodes.json`（「OSM 形状 + 年份」的中间层）和 `recipe.json`（节点种子和参数）。同一份配方永远得到同一个街区；随机数按位置取，改一处不牵动别处。
- 页面 `docs/living/nodes/<q>/index.html` 只吃 nodes.json 和底账房屋几何，一张栅格图都不用。地标是代码部件（柱廊、粮仓长屋、水殿、蓄水池穹顶、救济院），和房子用同一套 3/4 俯视画法。
- 远近分层：拉远时每个年份只烤一张整图；中间层按 256 像素分块、按 2 的幂级别烤，最多留 90 块；拉得很近时只画视口里的矢量。
- 南港基线（沙箱软件渲染，1100×1000）：首屏 1.0 秒，3 个请求，1.1 MB（gzip 后），堆 28 MB；z 0.48/1.2/2/4 平移约 60 fps；换年份 150 ms。旧版同条件下是 1.5 秒、31 个请求、8.8 MB、堆 88 MB。
- 还没接的：船队、48 年火场痕迹、人和敲门卡；古岸开运算（ancient_r）去掉了现代填海的细堤，西南那一大块现代填海地还在。

## 3D 渲染器（2026-10-17，主人「先看看 3D 效果如何」）
`docs/living/nodes/nangang/3d.html` 吃同一份 nodes.json，只换渲染器。为此给中间层加了一样东西：高程格 `elev`（每 16 像素一点，单位分米），2D 只用等高带，3D 要真起伏；这就是「换渲染器验 schema」测出来的缺口。
- 地面：高程格起伏，乘 1.3 倍夸张；陆地、等高带、港池、街、地标地皮画进一张运行时贴图披在上面。岸边按蒙版覆盖率在海底和陆地之间平滑过渡。
- 房子按底账占地立墙，屋顶是四坡顶或平顶，所有房子合成一个网格；地标用代码部件（柱廊立柱、纪功柱、粮仓双坡长屋、水殿半圆柱列、蓄水池穹顶、救济院院落）；防波堤是挤出的多边形，树是实例。换年份时整批重建，约 1 秒（沙箱软件渲染下测得）。
- three.js r160 放在本地 docs/living/nodes/lib/three（MIT，许可证随附），不走 CDN，国内打开更稳。
- 沙箱没有 GPU，软件渲染只有 1–2 fps，这个数字不能当真；真机帧率还没测。
