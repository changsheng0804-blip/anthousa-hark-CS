# yamen_v13 · 门牌 × 户籍 × 官府

——Hark（刘线）

把 v7 街网、v8 官府绑成一个系统：每户先有门牌（街名 + 号），户籍以门牌为键，官府每个职位有衙署门牌、辖区写成门牌段，五条流程按门牌查出要投递的衙署顺序。AF40 编号，AF41–70 逐年增量。结构见 SCHEMA.md，数字见 results.json。

## 关键数字
- **门牌覆盖**：AF40 / 50 / 60 / 70 在册户 10,713 / 15,296 / 16,577 / 17,633，无门牌户都是 0；有门牌的街 85 / 98 / 99 / 101 条。门牌键在每年户籍里唯一。
- **AF41–70 地址事件**：新编 7,340（插号 6,559、街头前插号 87、上游门牌 352、新号 342），改址 162（全部是新街开通），改名 360（AF48 弯弯巷→新二街、香料巷→新一街、铁匠巷→新三街、黑狗二巷→新五街、酸酒二巷→新四街；AF54 运水人巷→运水人池街），注销 412（全部是拆毁）。连 AF40 底号共 19,004 条，写入 addr_history.json.gz（153 KB）。其中 393 条改址/改名带当时的坊长户与区长户。
- **账本里没有道路被拆**（19 条账本道路、上游街都没有拆毁年），所以真实年份里「道路拆除」改址为 0。补了一次合成测试：在 AF70 的状态上拆掉 `r_north3`，同时把三棵松巷改名。结果 1,949 户改址（道路拆除）、621 户改名；增量 22 ms，与按街重放的结果相同。
- **附号**：AF70 有 7,899 户（44.8%）门牌带附号。按附号长度：1 位 6,199、2 位 1,623、3 位 77，最长的是 `路·north3 559AAF号`。原因是「不重排、只插号」：老街两户之间后来补建了几十户，都只能挂在前一户号下面。
- **与上游门牌对照**（上游 addr.json 里有、本模型当年也有门牌的户）：AF60 可比 4,359 户；街相同 1,546 户（35.5%）；门牌完全相同 784 户（18.0%）。这 784 户全部来自「能对上就用上游号」。街相同的户里，单双相同只占 50.7%，跟抛硬币差不多：上游把房子挪到了街边地块，账本房屋还在原质心，所以在街的哪一侧推不一致。
- **3,168**：已复现。它是上游门牌表刷新（04c3bec 前后两版 addr.json）里，AF60 所在街（按街的现名）变了的户数，属于事实版本差，不是城里某一年发生的改名。本模型里 AF60 与 AF40 街名不同的有 176 户，其中 151 户是 AF48/54 改名造成的；街键不同的只有 25 户。176 户与 3,168 户重合 128 户，Jaccard 0.040。**两者不相符，因为不是同一个量。**
- **衙署**：AF70 共 465 个职位实例，空缺 15 个。衙署依据：任职户门牌 437、辖区设施本身 22、对应公共建筑 5、中心性代理 1（城市长官）。在任者没有衙署门牌的情况为 0。
- **辖区门牌段**：各年把门牌段解回成员户，结果与 v8 辖区成员完全一致（353 / 433 / 442 / 465 个实例全过）。AF70 每个实例的区间段数中位 5、最多 322（d_forum×铺面 的行会头，662 户）。坊长中位 4.5 段（中位 11 户）；区长中位 99 段（中位 2,890 户）。
- **路由**：每次查询平均 7.8–8.1 µs（预建索引每年 0.18–0.22 s）。每年随机抽 1,000 户，与 v8 关系图的「隶属」边比对：AF40 / 50 / 60 / 70 都是 1,000 / 1,000 一致。第一次跑时 AF60 有 164 户不一致，全是阿里乌户：v8 的主教（尼西亚）是全城职位，阿里乌户也连到他。路由已改成同样的口径，七条线不变，另列全部 14 类归属。
- **增量 == 重建（AF40–70 共 31 年）**：v7 门口表 31/31、v7 户籍记录 31/31、门牌 31/31、地址事件 31/31（两边都是 19,004 条）、户籍 31/31。
- **耗时**（每年中位 / 最大）：门牌局部更新 1.17 / 5.8 ms；变动检测（全表对比门口）3.2 ms；门口提取 13.4 ms；v7 增量 12.9 / 130 ms；户籍增量 31 / 47 ms（每年改动行中位 1,119）。从头生成：v7 建网+户籍+门口每年 577 ms；全部 31 年门牌按街重放 441 ms；户籍表每年 37 ms。
- **每户字节**：户籍 gzip 18–19 B/户（AF70 337 KB），JSON 原始约 202 B/户。

## 三栏

### 一、硬件 / 账本推出的
- 街、街段、门口位置、沿街累计距离、门口在街的哪一侧：来自 v7 街网（账本道路 + 上游街段经仿射），以及 v7 的门口垂足。
- 上游街名、按年改名（AF48、AF54）、开街年：来自 streetnames.json；上游门牌号来自 addr.json。
- 户籍各字段（区、坊、教区/会众、供水组、粮仓、哨、行会）：来自 v7 materialize；职位、任职户、户主人物 id：来自 v8 cast.py（规则 + 填职引擎原样运行）。
- 设施门口（教堂、蓄水池、粮仓、城门、城墙段）：来自 v7；兵营、各类公共建筑的位置和建成年：来自 world.json。
- 改址事件的原因（新街开通、拆毁）：来自 v7 逐年事件。

### 二、模型假设（可改，改了数字就变）
- 编号规则：沿街从起点编；叉积 < 0 一侧为单号；AF40 定底号；之后新房插号用附号（大写 = 在前一户之后，小写 = 在本侧首户之前）；不重排，号不复用；门口在同街同侧内挪动不改号。
- 能对上就用上游门牌：同一条街、单双相符、号没被占。新号从 max(已发号, 上游最大号) + 2 起，给上游预留的号让路。
- 账本道路的街名 = `路·<id>`。账本里的 The Mese（r_mese）和上游的梅塞大道是两条街键，没有合并。
- 衙署：城市长官用中心性代理，即 AF40 全城路口里调和中心性最高者（j:503.96,446.89）旁最近的房屋 h4411，门牌梅塞大道 113号，户毁才重选；粮政官设在最早的在立粮仓（granary_founder）；水政官设在最早的在立蓄水池（cistern_founder）；夜巡长设在兵营；主教座堂取面积最大的在立尼西亚 / 阿里乌教堂（church_megale / AF70 church_arian_brick）；区长、坊长、行会头的衙署就是任职户，空缺就没有衙署。
- 公共建筑和设施门也占门牌（会影响附近户的号）；辖区门牌段只按户计。
- 辖区门牌段的语义是「本侧在册户按门牌序连续的一段」，不是号的数值区间（附号使数值区间失去意义）。
- 路由的上级链按户自己的辖区取（与 v8「隶属」边同口径）；v8 里坊长的上级区按坊内多数户取，两者只在跨区坊里可能不同（本版没有统计）。

### 三、推不出的
- 真实门牌制度：拜占庭城市是否沿街编号、单双分侧、附号写法，账本和上游都没有。这里的规则是现代式的假设，只用来做主键。
- 账本道路的中文街名，以及账本道路和上游同名街是否为同一条街（The Mese ↔ 梅塞大道）。
- 房屋在街的哪一侧：上游地块与账本质心推出来的结果只有 51% 一致，推不出谁对。
- 城市长官官署（praetorium）的位置，以及粮政、水政的实际办公地。账本里只有粮仓、蓄水池、兵营这些设施，没有官署。
- 门牌何时、由谁颁发，改名是否真的改了门牌上的字，户主在改址时是否登记。地址事件只给年份，没有月日和经手人（坊长户、区长户是按年推出来的）。
- 户与房分离（租户、一房多户）：账本一栋房 = 一户，所以门牌和户一一对应。

## 发现（只陈述数字）
- v7 坊里的「深层」（离街每 20 单位另起一层）与沿街门牌顺序不一致。同一侧街面上，`坊@360.00,480.00>371.73,477.65.0`（61 户）和它的 `|深1`（36 户）在 `路·mese 423B–457` 号之间交错，各自要 23 段才写得完。坊长辖区段数的最大值 157 出在 `坊@572.50,492.50>576.00,480.00.0|深1`（252 户）；AF70 的 71 个深层坊段数中位 24，355 个非深层坊中位 3。如果想要「一段门牌 = 一坊」，坊需要按门牌顺序切，而不是按离街距离分层。
- 附号多半出在补建密集的老街：AF70 带附号的户从 AF40 的 1,522 增到 7,899。改成「每 10 年按门牌顺序重编一次 + 记改址」，可以把附号清掉，代价是每次重编要多出几千条改址事件（本版没有做，要求是不重排）。
- 真实 30 年里改址只有 162 次，全部是新街开通把门口吸走；改名 360 次全部集中在 AF48、AF54 两年。
