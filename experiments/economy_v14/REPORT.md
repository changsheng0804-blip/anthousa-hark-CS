# economy_v14 · 经济活动体系（门牌 × 户籍 × 官府 × 硬件）

——Hark（刘线）

在 v13 门牌户籍、v8 官府之上加一层经济：每户一种生计，每笔钱/粮是一条「付方门牌 → 收方门牌/衙署」的流，带类型、数量、规则来源。逐年 AF40–70 计算，每年守恒、对账本。地下数据管线，不做页面，不写故事。结构见 SCHEMA.md，数字见 results.json 与 ledger_reconcile.csv。

## 关键数字
- **规模与耗时**：AF40 / 50 / 60 / 70 在册户 10,713 / 15,296 / 16,577 / 17,633，每年流 100,267 / 152,221 / 165,927 / 176,402 条。AF40–70 全部 31 年全量 14.3 s（含载入 v13 缓存与 v7 街网 ≈2 s），每年中位 0.21 s。列式文件 flows_AF40/50/60/70 = 0.60 / 0.91 / 1.02 / 1.08 MB（目标 < 3 MB）。
- **守恒**：31 年每类流「付 = 收」，最大误差 1.9×10⁻⁸ 份（浮点）。全城货币（户 + 各库）年变化 = 外部流入 − 外部流出 − 随拆毁户注销的欠账，最大误差 5.7×10⁻¹⁰。逐个实体：年末现钱 = 年初现钱 + 收 − 付。
- **对账本 / v4**：31/31 年户数 = world.json 在立房屋数。31/31 年口粮到户总量 = 账本 food_cap（153,202 / 173,202 / 193,202）。31/31 年房税 = 0.5 × 账本房屋数。与 v4 比：口粮收入 AF51–70 逐年相同；房税差了一个房屋口径。v4 用的是 v3 户籍的 15,268–16,281 栋，账本是 15,417–17,633 栋，所以 AF70 是 v4 7,747.5 对本轮 8,816.5。
- **生计**（曾在册 18,045 户）：雇工 10,484、码头脚夫 841、面包 1,835、手工铺 2,117、作坊 724、港货商 562、运水人 411、营造 492、体面户 368、兵户 211。来源：上游第 9 栏 4,578 户（25%）；其余是假设，其中同街分布 4,096、同坊分布 770、距离先验 8,601。
- **AF70 一年**：口粮 193,202 份粮；宫廷采购（皇库付）34,052；工钱 29,286，加公役 3,819；买卖 31,233（面包 10,347、水 7,794、手工 7,899、港货 5,192）；房税 8,817，人头税 3,527，上交皇库 5,181；奉献 5,290，施舍 338；租金 6,227；借贷 4,458，还款 4,219。

  增量的做法：从反事实那一年的结果出发，K1 每户固定项只重算输入变了的户，K2 工钱只重算脏区，K3 买卖只重算签名（实际卖方、价格、预算比例）变了的买方；粮、税钱上缴、奉献、施舍、上交、借贷这些聚合项每次全量重算。4 个事件算出来都与全量重算逐行相同（行哈希一致）。**增量没有更快**：每户派生量（市场节点、价格、门牌序）和脏集检测（87–103 ms）都是 O(n)，K2 的脏区一个事件就覆盖 4–5 个区（全城就 5 个区），聚合项本来就占大头。到 1.8 万户这个规模，全量一年 0.2 s 已经够快。

## 已知问题
- **货币越积越多**：全城货币从 AF40 的 8.4 万涨到 AF70 的 84.6 万份。每年外部净流入约 2.9 万，大多沉在库里，AF70 尼西亚主教库 112,661、城市长官库 56,632。原因是奉献 5,290/年，但施舍只有 338（「< 线」的户很少），公役也只花超过门槛的一半。v4 的主教是「留 κ=40%」、施舍按需，本轮沿用了。要让钱回流，得给主教 / 城市长官加支出规则，这需要另定假设。
- **无房东租户**：AF70 有 899 户。v2 的 cap 6 加上「AF40 有房户才能当房东」，新区（d_exokionion 等）没有足够的房东。
- **v4 房屋口径不同**（见上），对账时只按账本对，v4 列出来作参照。
- 距离都是直线距离，没走 v7 街网（只有配给点、供水组、教区用的是 v7 的走街结果）。
- 事件的反事实只撤掉事件本身，没有重跑 v7（比如火后坊的重划照事件年）。
