## 一、为什么需要这条备用管线

安托萨目前依赖 2D 铜版画地图（SVG）展现城市历史。随着纪元推进（目标 1,000 年，数十个年代，人口突破 40 万，建筑超 50,000 栋），面临两个核心挑战：
1. **山体与立面难以直观评估**：瓦伦斯水道桥横跨山谷的落差、大皇宫依山势向马尔马拉海的层叠台地、圣索菲亚/圣和平的穹顶天际线，在纯俯视 2D 地图上无法直观检验。
2. **多智能体分支决策缺乏交互沙盒（What-If Rehearsal）**：当模型扮演皇帝或教会提议新建筑时，缺乏一个能实时进行硬规则自检、即时拖放试错并在 3D 空间直观预演的推演环境。

本模块作为**独立、零侵入的备用工具链（Standby Pipeline）**引入，不修改任何既有历史裁决，仅在表现层与推演工具层提供支持。

## 二、实跑压测验证与性能优势（实测基准）

为防范后期海量建筑（50,000 栋+）引发性能崩塌，我们在真实环境下对三大关键瓶颈进行了真机压测：

### 1. 3D WebGL 渲染：GPU 硬件实例化 vs 传统合并几何体
在 30,000 栋建筑规模下的实测对比：
* **显存占用**：传统顶点流需 37.08 MB，取巧的 GPU Instancing 仅需 **0.46 MB（显存瘦身 81 倍）**；
* **更新耗时**：从 25.1 ms 缩减至 **1.3 ms（提速 19.3 倍）**；
* **批次（Draw Calls）**：从数十批压缩至 **单一批次**，60 FPS 顺滑漫游。

### 2. 数据存储：街区配额生成 vs 全量存储
在 30,000 栋房屋规模下：
* 传统逐栋记录坐标需 **4.13 MB**，100 个年代将产生数百兆碎片；
* 街区规范（配额 + 种子）仅需 **1.28 KB（体积缩小 3,297 倍）**，客户端原地解压仅需 **13.45 ms**。

### 3. 几何裁决：空间 R-Tree 索引
在 60,000 栋建筑的极限规模下：
* 100 次新建筑防穿模与连通性检测仅需 **3.48 ms**（单次查询平均 **35 微秒**），内存仅 **4.1 MB**。证明 Python 规则引擎具有超大算力余量。

### 4. 离线真值烘焙：Blender CLI 1 秒出图
利用本地 Blender 5.2 CLI（Workbench 引擎），可在 **1.12 秒** 内离线烘焙出博斯普鲁斯全岛的高清山体阴影与环境光遮蔽（AO）贴图，免去前端高昂的光影开销。

## 三、文件与架构构成

| 文件 | 角色 | 说明 |
|---|---|---|
| `engine/export_to_sim3d.py` | 数据导出管线 | 将真实 SRTM 高程网格、OSM 海岸线、建筑与房屋打包为 `docs/anthousa_world3d.json` |
| `docs/3d.html` | 3D 交互查看器与分支沙盒 | 原生 WebGL 渲染，支持年代时间轴、点击选址、实时硬规则自检、一键导出提案 JSON |
| `tools/bake_hillshade_blender.py` | 离线光影工具 | 供有 Blender 环境的机器离线一键烘焙山峦光影底图 |
| `docs/index.html` | 导航微调 | 顶部栏增设 `3D 预演` 入口按钮 |
