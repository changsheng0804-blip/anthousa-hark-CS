# CS 线 · 街区生产线

目标：用底账「长」出一个新街区，人只做一件事——挑。

```
底账 world.json ──grow.py──▶ 街区数据 + 引擎草图（每栋房子、路、港、公共建筑、火烧地，逐栋对齐）
        │
        └─ 草图 + 已有画作的风格 ──AI 画师（并行 N 张）──▶ 候选画
                                                    │
                       critic.py 自动评分（房子命中率 / 空地干净度 / 水 / 火烧地）
                                                    │
                       reroof.py：从 AI 画里剪下屋顶当零件，按底账一栋一栋铺回去
                                                    │
                       页面（同一份 index.html，scene.json 换一个街区）──▶ 所有者：留 / 再来
```

## 一个街区怎么长出来（南港是第一个）
1. `python engine/build_all.py` —— 从提案重建 world.json。
2. `python tools/cs/factory/grow.py nangang 445 418 40 50 60` —— 截世界框（128×144，与已有街区同比例），出 houses.json、frame.json、每个关键年代的草图 base_Y.png。约 3 秒。
3. 每个关键年代把草图 + 风格参考图交给 AI 画师，各画 2 张（提示词要点：每个红块就是一栋房子、位置不许动；火烧地、港、公共建筑按草图）。
4. `python tools/cs/factory/critic.py nangang 50 候选1.png 候选2.png …` —— 选分高的，再用眼睛看一眼。
5. `python tools/cs/factory/reroof.py nangang 50 候选.png ng_af50.jpg` —— 屋顶归位到底账。约 5 秒。
6. 写 scene.json（关键年代、标题、此刻滚动条）和 city.json 的地标（名字和故事只用 chronicle 里有的事实）。
7. `node tools/cs/check_talk.js`（把目录换成新街区）—— 每扇门的回答零空值。

## 第五段：验收（accept.py）—— 拉取 → 比对 → 验收 → 修改

`python tools/cs/factory/accept.py nangang [--pull] [--live]`

- 拉取：上游底账有没有新提交（--pull 合并）；world.json 过期就重算；用最新底账把街区重长一遍，逐栋和线上数据比。
- 比对：页面上的数字（栋数、烧毁数）、地标年份、地标是否在框内、静态文字有没有串别的街区、「怎么做的」写的年代、街区之间能否来回走。
- 画面：房子对位、水、火场黑、灰烬是否漫出真实火场、公共建筑旁的房子有没有被吞掉；另出一张公共建筑目检表 `out/<q>_landmarks.jpg`（青框已建、紫框未建），机器测不准的「建筑画得对不对」看这张。
- 线上：每个文件线上和本地 sha256 一致。
- 结果写进 `docs/living/<q>/ACCEPT.md`，每个不合格项带「怎么修」。退出码 0 才算验收通过。

第一轮（建城 60 年版南港）查出 5 项，已修：
1. 亚历山大粮仓故事里第一个年份是 48（火灾），没写「建城 55 年」→ 改文案。
2. 南港静态文字串了干山的介绍 → 文字改由 scene.json 的 info 提供。
3. 50 年灰烬漫出真实火场 23.4% → reroof 保护区从「圆圈 + 15 像素」收紧到底账地块，现 5.4%。
4. 50 / 60 年狄奥多西粮仓旁的房子被吞（覆盖 0.18 / 0.53）→ 先贴保护区再铺房子，火场里幸存的房子也照底账铺上。
5. 目检表发现候选 a 把粮仓画成了烧剩的空壳（底账里粮仓没毁）→ reroof 加 DONOR：火场用候选 a，粮仓借候选 b。

## 第六段：打通（cs7）—— 底账一变，画和心跳自己跟着长

```
底账变了 ─accept.py --fix─▶ 只有房子变：repaint.py 照 scene.json 的 paint 配方重铺屋顶，只动变了的那几栋（量局部性）
                         ├▶ 公共建筑变了：报出是哪一座，只把那一块交给 AI 画，记进 paint 的 donor
                         └▶ heart.py 重算心跳位置：泊位、系缆桩、锚地、每艘船的水路、码头站人处、孩子爬的港墙、扛包到粮仓的路
```
- `heart.py <q>`：规则（借自 castle-town-sim 的「中心按规则放」）——泊位在离水 ≤8 像素的岸上，前面水深 ≥24、能从海上开进来、码头不压房子、离粮仓走得最近、港里的岸加分；港口多边形四周是墙，口子开在离粮仓最近、外面是开阔水面的那段；船走离岸远的水路；人沿街走（路 1、空地 2、穿房子 9）。目检图 `out/<q>_heart.jpg`。
- `repaint.py <q> [年] [--check]`：AI 原画存在 `raw/<q>/`，配方在 scene.json 的 `paint`。实测：50 年拆两栋房子，画只变 0.01%，一块。
- 新检查：港里画的是水（每年每个港）；心跳位置和底账算出来的一致。
- 第一次跑就查出：60 年两张候选都把狄奥多西港画成了一座大房子（之前的验收没查港）。已用 50 年那张的港局部补上。
- cs8：heart.py 还算「人走的网」（scene.fleet.walk：陆地 + 港墙顶的方向场，到码头一张、到港墙一张）。页面上每个人沿网走，check_fleet.js 硬查人不下水、船不上岸（来自所有者的「再来」）。

## 第七段：每小时一次的改善闭环（cs10 起）
发现 → 写检查 → 修一条 → 验收 → 推送或回滚 → 记账
1. 发现：所有者的「再来」（verdicts.json）＋ backlog.md ＋ 本轮自己看出来的（目检图用 read_file 看）。
2. 写检查：先写一条自动检查，确认它在修之前不过。
3. 修：每轮只修一条，只动南港和 CS 线自己的代码，不碰底账。
4. 验收：check_fleet / check_card / accept.py 全过才推送；不过就 `git reset --hard` 回到上一版，这一条在 backlog 里标「卡住」并写清原因。
5. 记账：nightlog.md 记一行（几点、修了哪条、新检查叫什么、验收几项过了几项）；backlog 里移到「已修」。

## 第八段：定律 + 查收图 + 少打扰（cs19 起）
- **定律**：见 LAWS.md，用 `laws.py <q>` 检查。accept.py 的「定律」一节会跑它，任何街区都适用。
- **查收图**：`review.py <q> --base csN` 在底账的水陆蒙版上标出从 csN 到现在改了哪里，输出到 out/<q>_review.jpg。
  - 改动分六种：新能走、不再能走、街、站位、船的水路、画面。
  - 每种改动至少圈一处样例，一共最多圈 6 处，每处左旧右新放大对比；其余改动只点白点、计数。
  - 底图上，红斜线是底账和画对不上的岸。
- **所有者每天只评一版**：每天 17:00（太平洋时间）把当天最新的一版连同查收图一起交给他，base 是他上次评过的那一版。中间推送的小版本不单独请他评。
- **心跳少转**：上游没有新提交、没有新的「再来」、backlog 没有可修的条目时，这一轮只做验收、不提交，然后直接结束。

## 第九段：蒙版生成（cs20 起）
1. `GROW_OUT=/tmp/ng python tools/cs/factory/grow.py nangang 445 418 40 50 60` 出底账草图 base_Y.png（蓝 = 水，棕块 = 房子，灰 = 公共建筑）。
2. 缩到 976×1088，只给「草图 + east_af30.jpg 风格参考」调 generate_image，提示词写死：蓝的地方才画水和船、岸线一像素不动。**不要给旧画**：给了旧画，AI 会照抄旧岸线（cs20 试过：给旧画时底账陆地画成水 1215 像素，不给时 127）。
3. 原图存 raw/<q>/ngY_ai_mN.png，挑底账陆地画成水最少的那张；改 scene.json paint[Y].src，跑 repaint.py、heart.py、laws.py，看定律四格数。
4. 蒙版合成（repaint.py 自动做）：AI 画的岸偏几像素时，底账是陆地或港墙、画上是水、离画上陆地 ≤32 像素的，用最近的画上陆地颜色补上。
5. cs21 三张都换完，定律四改成必须过：按 4 像素格量「底账陆地画成水」≤50（现在 0）。

## 第十段：码头逐年长（cs22 起，所有者提）
- heart.py 把画上的栈桥（不算港墙顶）按离泊位远近排队，港挖成以后港边 600 像素内住户每涨一截就建成一座；写进 scene.fleet.docks（from、8 像素格的 rects、根、每张关键年画的四周水色）和 pier_from。

- 检查：check_fleet「docks」。

## 第十一段：一条命令长一个街区（cs30 起）
`python tools/cs/factory/make_quarter.py <q> [--from 段名]`，配方 `tools/cs/factory/quarters/<q>.json` 只写这块地特有的：名字、框、关键年、地标中文名和一句话、街头气氛、链到哪个街区。
段：grow → scene（scene_auto.py，拷公用页面）→ paint（缺画就写草图 + PROMPT.txt、退出码 3，Hark 调 generate_image 存进 raw/<q>/ 再 `--from paint`；多张候选逐张铺屋顶交 critic，对位 ≥0.8 里挑底账陆地画成水最少的）→ land（land.py：走得上的网、城里的街，任何街区都要）→ heart（只有写了 fleet 配方的港才跑）→ streets → ground → render → accept --fix。
- 所有街区共用一份页面（模板 = nangang/index.html），accept 查一字不差；check_page.js 在 jsdom 里跑页面，每个关键年站着的房子数 = 底账。
- repaint.py 新增两步：底账陆地成片画成水 → 铺本画沙色；沙色校到 east_af30 的沙色（nangang 的配方 palette:false，原画不动）。
- streets_ng / ground_ng / laws / check_streets 不再要求 scene.fleet：没港就用 scene.walk；长街方向默认顺岸线；底账市场四周的地块是 market。
- 第一块：金角岸 jinjiao（框 440,210），中途零手写坐标；唯一的人工是 60 年第一张画沙地太橙，critic 判不过，多画两张候选后工厂自己挑中 m3。

## 第十二段：全城一张街网（cs31 起，所有者定的原则）
街区将来要拼成一座城，基础设施不许各自为政。规则分层、只读上层，见 CITY_RULES.md。
- `python city_streets.py`：按底账（大道、城墙、岸、坡、旧区）给整座城长街，写 city/streets.json。底账或规则一变，streets_ng.py 会自动先重跑它。
- streets_ng.py 不再自己长街，只把全城网裁到框里；配方里不许写街网参数。
- 改街网只能改 city_streets.py 的参数表 P（全城一张），不许为某个街区加例外。
- cs32：地面颜色只从 city/palette.json 来（沙、水），ground_ng.py 统一，check_palette.py 在 accept 里查。

## 第十三段：瓦片实验（cs33，推演中）
- `python tile_bake.py [年…]`：把所有 street_layout 街区按世界坐标烤成瓦片金字塔 docs/living/tiles/<年>/<级>/<x>_<y>.webp（级 0 = 32×32 单位 = 455 px），写 meta.json（时间、每级块数与字节、拼回 PSNR）。
- docs/living/tiles/index.html：只拼瓦片的全城页；`node tools/cs/check_tiles.js` 量各级一屏画几块、下多少字节。
- 街巷级（cs33b）：屏幕上 1 个瓦片像素 ≥1.15 个屏幕像素时换手——地面用 tiles/g/<关键年>/ 的纯地面瓦片，街和房子取 tiles/vec/<x>_<y>.json（带建成/拆毁年，换年不重下），浏览器按 render_ng 同一画法画。
- 人和船（cs33c）：只在视口和外面一圈瓦片里活，离开就收掉。人走烤瓦片时验过全程是陆地的街（段末位 w），每 15 栋站着的房子一个人，一块至多 30；船只在 8 像素水格里挪，船心四周 4 格都是水（船身约 44 像素），每 400 个合格格一条，一块至多 3。静的一层存在离屏画布，只在镜头或数据变了时重画，每帧只画人和船。
- 还没做：地标 AI 单画；程序水面；人和船接上各街区的心跳（粮船日等）。
- 心跳（/goal 2 项 4a）：`python tile_heart.py <q>` 把街区页的粮船日（cs6）和家户推演原样剪成 tiles/heart/<q>.js，页面里 HEARTS 列表点名的街区进框+街巷级才载入；炊烟跟房子走。检查 `python tools/cs/check_heart.py`。街区页改了这几段要重跑。

### 立面前后次序（zsort.py，2026-10-14）
页面按 vec 里每栋房的 h[2] 升序画立面贴图。h[2] 原是脚印最南端 y，单键排序会把相邻高窄房、凹口里的房盖错（全城 137 对）。
zsort.py 对立面可能重叠且年份相交的房子按脚印在共同 x 范围内谁更靠南建边，全城一次拓扑排序，把名次写回 h[2]；tile_bake.py 写完 vec 后自动调用。
`python3 zsort.py --check` 数错序对，应为 0。

### 叠层最小实验（traces.py + check_traces.js，2026-10-14）
- 年份轴按年连续：建城前烤好的几档 + 建城后每一年；栅格取不早于它的那一档（tile() 里换），矢量房子/街巷/痕迹按这一年精确画；事件在自己的年份亮。
- traces.py → tiles/traces.json：旧址（destroyed 的结构，原线浅痕）、旧石（spolia_from）、火场（vec 里火灾年拆的房子留焦痕 8 年，卡上列火场上后建的结构）。只从底账推，每条带 src。
- check_traces.js：出处、编年史原句、焦痕覆盖、按年显隐、出卡与「回到第 N 年」。check_chron_page.js 已按连续年份改。
- 已知：全城级栅格仍是十年一档，拖到档与档之间时全城级的房子按下一档显示；街巷级精确。

## 栅格减档审查（2026-10-14）
tile_thin.py --dry：级≥1、和根瓦片比"明显变化像素<0.5% 且任一 16px 小块≤4%"才算看不出。结果只有 17 块 / 137K 合格（级 1–4 共 ~10MB），
其余每个十年档都带真实局部变化（新街坊、第 48 年火场焦痕、码头、船）。结论：不减档；工具留作审查，未在 tile_bake 里启用。
