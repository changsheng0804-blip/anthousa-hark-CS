# 居民节点（试作，2026-10-18）
主人：「居民首先得能被看见」「不能是纸片人」，角色的真正形态是他怎么活。所以不写人，写行为。
- `people.py <q> [年份]`：只读 nodes_net.json，按规则挑人（不用随机数），推出步态（步速/步长/前倾/起伏/摆臂/跛）、负重、一天五段（黎明/上午/正午/下午/傍晚）、同伴、地位（有身份的走街心，别人靠边），写 `docs/living/nodes/<q>/people.json`。走路按真实步速算时长，停留补满时段。
- `graph.py`：把街段在丁字口、十字口切开再连成图，用来寻路（南港 60 年：5533 个节点，主网 5501 个）。
- 渲染：`docs/living/nodes/people/people.js`，关节人形（髋、躯干、头、两臂两节、两腿两节），步子的相位跟着走过的米数走，所以脚不会在地上滑。
- 入口：`scroll.html?n=net&people=1`，页面上不写字（无字测试）；加 `&key=1` 看答案，`&t=秒` 跳到一天里的某个时刻。
- 南港五人：老渔夫 + 孙子（尤利安港）、商人 + 仆人（主街→狄奥多西广场）、挑水的女人（坡上，高差约 11 米，一天三趟）、粮仓搬运工（亚历山大粮仓↔栈桥）。原计划的修士换成了搬运工，因为南港底账里没有教堂。
- Mac M4 实测（BrowserOS，线上 02eb111）：跟拍五个人和看长卷时都是 100 fps（屏幕刷新上限）。
- 还没做：遇到城市事件时的反应；和旧的滑行路人合并（打开居民时旧路人先收起来了）；渔夫那座栈桥在南港框的东边上，框外的海是空的。

## 姿势引擎 + 人群（2026-10-19）
- `pose.js`：统一姿势通道 / 意图→参数分布 / 种子 4 选 1 打分 + 同路线取最不像 / 叠加手势（回头、擦汗、伸手、叉腰、躬身）。五个主角和人群共用。
- `crowd.py` → `crowd.json`：700 条路线，每条 = 一户真实房子的门 → 用途推出的去处（打水 296、跑腿 192、市场 172、搬运 32、广场 8）。
- `crowd.js`：每部件一张 InstancedMesh（22 次绘制调用，与人数无关）；近景关节人 / 远景柱；位置是时间的纯函数；商人经过时旁人让路躬身。入口 `&crowd=N&full=300`。
- Mac M4 实测（线上 0454fae）：1000 / 3000 / 6000 / 10000 人，长卷和街上跟拍都 100 fps（刷新上限）；10000 人时同时在街上 8288 人，每帧算人 1.9–2.2 ms。
- 10-19 续：叠加手势只给镜头 25 米内的人（近景 300 人每帧 3.8→2.9 ms，Node）；长卷缩远时远景柱放大（最多 5 倍）。Mac 实测 6000 人跟拍商人，t≈1017 有人躬身让路，100 fps。长卷里人流仍只是主街上的细点，还不够显眼。

## 信息层：指到才出现（2026-10-19）
主人定的：指到才出现，因为运算压力小。鼠标停在人头附近 28px 以内，就出一张签：身份、此刻在干什么、一条底账事实或关系（主角写「在这住了 59 年」「老渔夫的孙子」，人群写「住在民居」「码头上的人家」）。不指就不算；指的时候只在这一帧视野里的人当中找最近的一个，每次移动鼠标最多算一次。鼠标离开 70px，签就收起来。
Mac 实测：跟拍商人时指到他，出「商人 往狄奥多西广场去 / 主街带柱廊的铺子」，仍是 100 fps。
踩过的坑：写信息层时用了字段名 o.leg，跟腿的颜色重名，近景一画就报错，整个动画循环停了，fps 角落还停在旧读数 100。现在改叫 o.seg。

## 长卷人流视觉增强（2026-10-19）
缩远（farBoost > 1.3）时：远景柱按「在干什么」上色（打水蓝、扛货褐、赶集黄、去广场紫、办事绿，和左下角图例同色）；每人在街面上多一张半透明椭圆，走路的拉长、停着的铺圆，叠起来就是色带和人团。只多一次绘制调用，不加逐人计算。
Mac 实测（6000 人，正午）：整城视图 4888 人全画，人群每帧 2.2 ms，100 fps。看得出蓝色打水流从坡上小巷汇向喷泉，主街是黄褐和绿色。
踩过的坑：色带一开始画在 o.y−1.5，埋在街面下面；后来又有一个行尾注释把 compose 吞了。现在画在 o.y+0.4。
还可以调：整城视图里远景柱的墨线偏重；蓝色占得多，是因为底账里打水路线本来就多（296/700）。
