## 0 一句话结论

- **AF70 净收入贫困率：10.37% → 8.36%**（1,830 → 1,475 户，目标 ≤9% ✓）。收入口径从 8.20% 降到 6.89%。净收入 Gini 0.502 → **0.502**（≤0.55 ✓）。失业+零工 7.1% → **9.2%**（在 5–15% 区间内 ✓，但比 v19 高）。
- **几乎全部降幅都来自体面户**：体面户贫困 326 → 82。**手工铺上限只是把贫困从铺主挪到了雇工里**：手工铺贫困 631 → 252，同时雇工贫困 718 → 979。分解组的结果是：只做体面户（G4）得 8.38%，两项都做（G2）得 8.36%；只做铺数上限（G5）得 10.19%（v19 为 10.37%）。原因是全城手工需求本身不够，城里也没有空着的工位，转业的人要么挤进公役，要么去做零工。
- 骤降路径：AF65 **11.4%**（≤25% ✓，v19 9.5%），AF66 **11.9%**（≤15% ✓，v19 11.5%）。两项都在目标内，但都比 v19 略高。AF65–70 累计 <线户·年 10,928 → **9,531**；相对各自基准多出的部分 +2,502 → **+2,352**。
- 到港 ×0.5（如实）：失业+零工 **38.5%**（v19 36.6%），无人借 **3,456**（v19 3,452），净<线 29.2%（v19 31.6%）。长期萧条下仍然撑不住，这部分本轮没有处理。

### 1b 体面户：户籍里它们是什么（`diag.v19.fine`）

- **v14/v15 户籍并没有「身份」这一栏**。体面户的定义是：这栋房屋所在地块的街区功能为 `fine`（体面人家）。生计按这条规则确定：`livelihoods()` 中 `liv[fn == "fine"] = 8`。
- 366 户里，街区功能的来源是：上游第 9 栏 102 户；同街分布推断 29；同坊分布推断 1；**距离先验推断 234（64%，假设）**。所以大多数体面户本身就是推出来的。
- 户籍和账本里能看到的属性只有：房产（出租 6–7 栋的 25 户、自住 1 栋的 210 户、无房 131 户，其中 85 户是租户）、v8 任职（7 户领俸给）、AF40 初始现钱 30。
- **地主、食租者、退役、官员家眷、寡妇这些身份，户籍里都没有**。rules_v3 的「缺男丁（14 岁口径）」只覆盖页面那一街区的人口，对不上本城 v7 的房屋，所以没有用。下面按身份给收入，身份全部由「可见属性 + 假设」来定。

## 2 改了什么（全是假设，`results.json → params.new`）

1. **手工铺上限**（静态，做法同 v16 的面包户再平衡）
   - 每个节点留下的铺数 k = 满足「D/(k + 作坊数) + 每铺出口额度 ≥ `craft_rmin` 7.0」的最大 k，每个有铺的节点至少留 1 家。
   - **出口额度总量固定**：手工铺出口总额 = 转业前铺数 × 1.5（随到港量变化），由留下的铺子平分。每铺 1.5 → **1.986**（按历年在册铺数之比 2,117/1,599）。理由是出口需求由船商定，不随铺子多少变化。
   - 过剩的铺子在本节点内按确定性散列抽出，概率为 1 − k/n，作用于历年全部在册的手工铺：**2,117 → 1,599，转业 518 户**（AF70 在册 2,105 → 1,587）。
   - 转业去向：
     - 离商港直线 ≤60 → **码头脚夫**（港口）：4 户；
     - 其余 → **雇工**（转作他人作坊或铺子的雇工；铺子的顾客自动流向本节点留下的铺，相当于合并）：514 户。
   - **没有设「出口作坊」这个去向**：出口总额固定，转成作坊就等于凭空多出每户 10 的出口需求。
2. **体面户按身份给收入**（每年按当年属性判定，行类 k=9，增量与重建一致）。判定次序如下：
   1. 有出租房 → **房东**：靠现有的 v2 房东规则拿租金，租金流已经绑定在各租户门牌上，不新增流。
   2. v8 任职 → **任官**：靠已有的俸给 / 官俸，不新增流。
   3. 自住有房 → **城外田产**：新流 `田租(城外田产)`，从新外部源「城外田庄」流入，每户每年 4.5。
   4. 租住者按散列取 30% → **年金 / 俸禄遗属**：新流 `年金(皇库)`，每户每年 3.5。
   5. 其余 → **无来源**：如实保留，靠积蓄、借贷和施舍。
   - AF70 合计：田租 936、年金 129.5（守恒按外部流入记账）。

## 8 守恒与对账（全部通过 → 已提交）

- 基准 31 年每类流「付 = 收」，最大误差 1.87 × 10⁻⁸。货币年变化 = 外部流入（新增「城外田庄」）− 外部流出 − 随户注销的欠账，最大误差 7.9 × 10⁻¹⁰。×0.5 / ×1.5 / 骤降路径分别为 2.6 × 10⁻⁹ / 1.3 × 10⁻⁹ / 1.0 × 10⁻⁹。
- 户数 = 账本在立房屋、口粮到户 = food_cap、房税 = 0.5 × 账本房屋：基准、×0.5、×1.5、骤降路径都是 **31/31**。
- 5 个事件增量 == 重建 **5/5**（AF48 火灾、AF55 新粮仓、AF57 新市场、AF62 新街、AF65 到港骤降）。体面户收入行每年全量重算（k=9），增量路径与重建一致。
- `flows_AF40/50/60/70.json.gz` = 0.78 / 1.18 / 1.30 / 1.41 MB，都 < 3 MB。households 新增两个字段：
  - `craft_conv`：v19 的手工铺转业 = 1；
  - `fine_role` / `fine_role_names`：体面户身份。

## 9 已知问题 / 推不出

- **手工铺上限对总贫困几乎没有作用**（G4 对 G2）。手工需求的总量是由户需求表（q_craft 0.5 × 价，体面户 ×3）加上添置决定的。铺子少了，钱只是集中到留下的铺；转业的人需要别的营生，但城里的劳动需求没有增加（留下的铺子营收 7–9，按每工产出 6 算，几乎雇不了人）。真正缺的是工位，或者城外需求。
- 转业户按门牌序进入公役，挤掉了原来的公役人选。这是 v19 公役规则「门牌序」带来的副作用，没有改。
- 铺数上限用的是 v19 基准 AF70 的实测需求，一次定下、全程静态。×0.5 和骤降路径里不会再调整（萧条时不会有更多铺子关门）。
- 体面户「无来源」92 户里有 82 户仍贫困。户籍分不出寡妇、败落户、退役，所以不再加收入。
- 田租 4.5、年金 3.5、年金比例 30%、阈值 7.0 都是假设或标定值，没有史料能定量。「自住有房 = 有城外田产」也是推断。
- `diag` 用 flows 里取整到千分之一的值重算，所以 1,476 和年度统计的 1,475 差 1 户。
